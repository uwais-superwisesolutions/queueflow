## 1. Auth model & base URLs

There are **three authentication realms**, enforced by middleware in `Backend.API/Program.cs`:

| Realm | Token | Issued by | Used on |
|---|---|---|---|
| **Org-member** (super_user / org_user) | Supabase ES256 JWT | `/api/auth/login`, `/api/auth/signup` | All `/secure/*` routes |
| **Client** (anonymous-ish portal user) | App-issued HS256 JWT | `/api/client/phone/confirm` | All `/api/client/*` routes (with explicit anonymous exemptions) |
| **System** | `X-Api-Key` header | (background services) | All `/secure/*` routes |

**Anonymous routes** (no token required):
- `POST /api/auth/signup`, `/api/auth/login`, `/api/auth/refresh`, `/api/auth/forgot-password`
- `POST /api/client/phone/verify`, `/api/client/phone/confirm`
- `POST /api/client/portal-links/{slug}/scan`
- `GET /api/client/orgs/{orgId}`
- `GET /health`

**Frontend base URL**: `import.meta.env.VITE_API_BASE_URL` → wired into a shared axios instance at `src/services/interceptor.ts`.

**Interceptor behavior** (`src/services/interceptor.ts`):
- Attaches `Authorization: Bearer <token>` based on whether the path is `/api/client/*` (uses client JWT from localStorage) or `/secure/*` (uses org-member access token).
- On `401`, retries once via the appropriate refresh path:
  - Org-member: `POST /api/auth/refresh`
  - Client: redirects to `/client` to re-do OTP (no refresh endpoint).
- Concurrent 401s are coalesced — only one refresh promise is in-flight at a time.

| Method | Path | Body | Returns | Frontend caller |
|---|---|---|---|---|

| POST | `/secure/bookings/{id}/decision` | `BookingDecisionRequest` | `BookingResponse` | `bookingDecision` |

| POST | `/secure/bookings/{id}/start` | `TransitionRequest?` | `BookingResponse` | `startBooking` |

| POST | `/secure/bookings/{id}/cancel` | `TransitionRequest?` | `BookingResponse` | `cancelBooking` |

**State machine** (`Backend.Business/Services/BookingStateMachine.cs`) enforces allowed transitions per actor type. Notable transitions:
- `pending_approval` → `scheduled` (decision: approve) or `rejected` (decision: reject)
- `scheduled` → `checked_in` (check-in) → `in_service` (start) → `completed` (complete)
- `*` → `cancelled` (most states; some restricted)
- `scheduled` → `no_show`, `checked_in` → `no_show`, `in_service` → `no_show` (recent addition; preserves audit trail; no SMS fires)

Each transition fires an SMS via `NotificationEnqueuer` where mapped.

## Cross-cutting notes

### Postgrest LINQ-visitor bug (Backend.Repos)

Multi-clause `.Where(a == X && b == Y && c == Z)` with 3+ conjuncts serializes to `and.(...)` with a stray dot and is rejected as `PGRST100`. Fixed by rewriting to flat `.Filter()` chains in:
- `BookingRepository.GetActiveByOrgMemberAsync`
- `BookingRepository.GetNextScheduledForMemberAsync`
- `NotificationRepository.GetRecentByBookingAndTypeAsync`
- `NotificationRepository.GetByClientIdAsync`
- `AvailabilityExceptionRepository.GetByIdAsync`
- `AvailabilityExceptionRepository.DeleteAsync`

Apply the same workaround to any new 3+ clause query.

### Cold SMS link convention

SMS notifications include a `?org=<uuid>` URL. The frontend (`src/lib/client-org.ts`) parses it first, then falls back to `localStorage` and `VITE_DEFAULT_CLIENT_ORG_ID`. The anonymous endpoint `GET /api/client/orgs/{orgId}` provides the branding for the landing screen before the user authenticates.

### Background services (not HTTP endpoints — for context)

Listed in `Backend.API/BackgroundServices/` and registered in `Program.cs`:
- `NotificationDispatcher` — drains the notifications queue every 30s.
- `DelayDetector` — 3-phase tick (overrun+cascade, late starts, wait-extended).
- `OtpCleanupService` — purges expired OTPs.
- `SoftHoldExpiryService` — moves expired holds to `expired`.
- `NoShowTimerService` — auto-marks past `scheduled` bookings as `no_show`.
- `SeatHeartbeatService` — releases stale seat assignments.

### DTO source of truth

All request/response DTOs live in `Backend.Domain/DTOs/`. The corresponding TypeScript types live in `src/types/`. When changing a DTO, update both sides — no codegen.
